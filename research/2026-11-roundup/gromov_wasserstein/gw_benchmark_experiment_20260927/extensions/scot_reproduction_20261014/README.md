# Reproduce a successful published GW example before comparing stochastic methods

This experiment starts from the released SCOT SNARE-seq **1,047-cell** feature arrays and author implementation. It is distinct from the prior 10,000-cell mouse-cortex experiment. The objective is the full squared GW discrepancy with uniform marginals, without a factor of one half. The reference optimizer uses entropy regularization; all reported comparison losses exclude entropy.

The reference follows the [published OTT/SCOT example](https://ott-jax.readthedocs.io/tutorials/quadratic/200_gromov_wasserstein_multiomics.html#alignment-and-evaluation): row L2 feature normalization, a binary correlation nearest-neighbor graph with `k=40` and self edges, undirected shortest paths, and separate maximum-distance normalization. It calls the unchanged SCOT `find_correspondences` with `epsilon=0.001`; omitted POT parameters retain their installed defaults. Source/settings are reproduced with recorded library versions, without claiming a bitwise recreation of the historical environment. POT supplies the first reference; no OTT run is implied.

The tutorial reports POT loss `0.016519975128479896` with marginal L1 error about `0.00133`. Our prior independent preprocessing calculation gives product-coupling loss `0.07045975745628463`. The reference records three distinct values: POT's published expression using prescribed marginals, the raw coupling's true objective using actual marginals, and the true objective after an output-only feasibility repair. Independent NumPy and POT contractions and small direct four-index tests check the loss. The raw and repaired reference plans are retained.

## Frozen execution order

1. A scheduled CPU job installs three pinned optional dependencies into this experiment's isolated directory, runs the new tests, reconstructs the exact released matrices and executes the reference solver. Source and feature hashes are checked. A prospective reproduction gate checks the expected starting objective, independent loss agreement, reference loss agreement within the documented tolerance, final repaired feasibility and repaired loss at most `0.025`. This establishes substantial attainable progress before releasing the comparison.
2. Twenty-seven A100 preflights exercise the full 1,047-by-1,047 instance, all method/prefactor combinations and the production precision. Existing numerical CPU and one-A100 proofs are reusable only when the complete numerical source hashes match. A factor-two runtime forecast and memory check must pass. Each job uses one A100, two CPUs and 16 GB host RAM.
3. Twenty-seven tuning runs use 20,000 updates on seed 810, one call of 1,024 independent coupling-pair samples per update, and product initialization. Every method has nine prefactor candidates. Selection uses the independently evaluated FP64 **last repaired loss at the fixed horizon**; it does not use the best online checkpoint or stop trials for poor loss.
4. Each selected method is evaluated for 20,000 updates on three fresh seeds, 811–813. A scheduled CPU job writes the comparison report after the dependency graph terminates.

FraMES varies `gamma0` over `{0.1,0.3,1}` and `mu_scale` over `{0.1,1,10}`, with `rho0=0.3`. Fresh-gradient entropic SMD varies its fraction of the theoretical step bound over `{0.01,0.025,0.05,0.1,0.2,0.35,0.5,0.75,1}`. MSBPG varies its theorem-compatible coupling fraction and momentum prefactor over `{0.1,0.3,1}` each. Exponents, momentum indexing and output selection remain those of the existing published-method implementations. SMD/MSBPG inner feasibility and guarded normalized primal-dual gap tolerances remain `1e-7`.

The reference preserves float64 distance matrices. All stochastic methods read those same files and use the existing float32 optimization arithmetic; final snapshots receive independent float64 validation. The small input cast must remain explicit in numerical interpretation. All three methods share the same pair-sampling oracle. The reference solver establishes an attainable objective; the stochastic methods form the primary performance comparison.

## Ruche execution and provenance

`stage_source.py` exports only committed, reviewed dependencies to a new immutable source directory. Data and pinned wheels are transferred separately with SHA256 manifests. `submit.sh SOURCE ROOT CPU_CHECKS GPU_CHECKS` submits the bounded dependency graph once and records job IDs. Jobs use account `fwllm`, CPU partition `cpu_short` or GPU partition `gpua100`, and the established project Python environment. Optional sklearn/joblib/threadpoolctl dependencies are installed only under the new experiment root. No running source tree or shared environment is modified.

Each production process has a 23-hour timeout within a 24-hour GPU allocation. Preflight forecasts must fit this limit with a factor-two margin. Array concurrency is capped at four one-GPU tasks, subject to the user's cluster quota and already-running work. Existing node exclusions for prior CUDA-unavailable failures are retained. There is no active monitoring loop, automatic resubmission or cancellation of other experiments. Any failed reference, numerical check, resource gate or full run prevents downstream selection/confirmation and retains failure evidence.
