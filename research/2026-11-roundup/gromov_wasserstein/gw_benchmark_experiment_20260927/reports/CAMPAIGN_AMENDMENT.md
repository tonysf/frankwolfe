# Prospective completion of the momentum comparison

Recorded on 27 September 2026 while the original development tuning campaign was still running, before a selected configuration or any held-out optimization result existed.

Protocol §8B explicitly requests a separately named momentum-matched stochastic KL-prox variant. The original frozen Stage C manifest includes the initial no-momentum comparator but omitted this subsequent ablation. The added method, `stochastic-kl-momentum`, completes that requirement. The original candidate grids, tuning budgets, selection rule, run IDs, and running immutable source are unchanged.

The new ablation inherits eta, its schedule, inner tolerance and cap from the selected no-momentum stochastic KL configuration. It inherits rho0 and the fixed rho_k=rho0/(k+1)^(1/2) schedule from selected smoothing FW. It uses the same q=128 trace-sketch family and first-sampled-gradient momentum initialization, reusing that gradient for the first update and drawing fresh samples afterward. Only the smooth gradient enters its momentum; KL feasibility handling has no Moreau penalty. These inherited settings receive no additional tuning. The comparison measures the effect of adding the prescribed momentum to the chosen KL configuration; it does not establish the best independently tuned momentum-KL method or extend the manuscript's FW theorem to KL updates.

Its runs clone the selected stochastic KL final cells: 55 product-start runs with 300 solver seconds and 55 randomized-start runs with 30 solver seconds, using identical frozen instances, stochastic seeds, initialization seeds, and checkpoint opportunities. This adds 18,150 nominal solver seconds (5.0417 GPU-hours), plus measured overhead, to the original 27.3167 GPU-hour plan. Separate supplemental configuration, selection and manifest hashes preserve this lineage. The additional runtime is required protocol coverage, not a result-driven parameter search.

The independently tuned row-projection comparator retains the same structural smoothing/momentum scheme, but its constants can differ from selected smoothing FW. Its comparison therefore includes parameter effects and cannot by itself attribute an outcome solely to replacing the row LMO. The exact-gradient smoothing ablation, in contrast, explicitly retains the selected smoothing constants and changes only its oracle.

Final Slurm tasks will use a single array with at most four simultaneous one-A100 jobs, split into shorter per-panel shards. This changes scheduling only. It does not shorten any solver budget, alter sample counts, or modify the scientific manifests. Existing running tuning tasks retain their original source and sharding; the unstarted fourth tuning shard was separately split into three equivalent subsets as recorded in `tuning_shard_rebalance.json`.
